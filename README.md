# code-evolution-diff

Сравнение двух версий кодовой базы по содержимому — для случаев, когда git-истории нет: остались архивы, zip-слепки, выгрузки с хостинга или копии «до/после».

Инструмент отвечает на вопрос: **что стало с кодом между двумя состояниями проекта** — сколько файлов осталось как было, сколько переработано на основе прежних, сколько появилось с нуля.

## Зачем

Бывает, что проект жил годами без версионного контроля: папки, архивы, «финал_2021.zip». Через несколько лет нужно понять, что именно изменилось — не глазами по диффу, а цифрами: сколько кода унаследовано, сколько переписано, сколько добавлено. Особенно когда версии разъехались по структуре каталогов и файлы переименованы.

## Как работает

1. **Нормализация.** Из файлов убираются комментарии (блочные, строчные `//` и `#`) и схлопываются пробелы — сравнивается смысл, а не форматирование.
2. **Три стадии сопоставления** для каждого файла целевой версии:
   - тот же относительный путь и то же содержимое → `identical`;
   - то же содержимое под другим именем или в другой папке (сравнение по хешу) → `identical`;
   - нечёткое сходство: кандидаты отбираются по пересечению 4-грамм, затем считается коэффициент `difflib` — если он не ниже порога, файл признаётся `modified`, иначе `new`.
3. **Отчёт** — по слоям (каталогам), в файлах и строках, плюс итоговые проценты.

Каждый файл получает ровно один класс, а найденный предок записывается в отчёт — можно проверить любое решение глазами.

## Установка

Нужен только Python 3.8+. Внешних зависимостей нет.

```bash
git clone <адрес-репозитория>
cd code-evolution-diff
python3 compare.py --help
```

## Использование

```bash
# сравнить два дерева, сгруппировать по слоям
python3 compare.py --baseline old/ --target new/ \
    --layers app/controllers,app/models,app/views,vendor/core

# отчёт в CSV: кто с кем сопоставлен и с каким сходством
python3 compare.py --baseline archive_2018/ --target archive_2021/ \
    --format csv --out report.csv

# другой язык или расширение и более строгий порог
python3 compare.py --baseline v1/ --target v2/ --ext .js --threshold 0.5
```

## Быстрый старт на готовом примере

В репозитории лежит `examples/` — три состояния одного проекта, на которых видны все три класса результата. Запуск:

```bash
python3 compare.py --baseline examples/course --target examples/v2021 \
    --layers app,config --format markdown
```

Ожидаемый вывод и разбор по файлам — в [examples/README.md](examples/README.md).

Параметры:

| ключ | назначение |
|---|---|
| `--baseline` | каталог базовой версии (предок) |
| `--target` | каталог целевой версии (потомок) |
| `--ext` | расширение файлов, по умолчанию `.php` |
| `--layers` | слои через запятую; без него группировка по первому каталогу |
| `--threshold` | порог сходства для класса `modified`, по умолчанию `0.30` |
| `--format` | `markdown` (по умолчанию) или `csv` |
| `--out` | файл для отчёта; без него печать в stdout |

Пример вывода:

```
| слой | база (файлы/строки) | цель (файлы/строки) | как есть | переработано | новое |
|---|---|---|---|---|---|
| app/controllers | 17 / 819 | 42 / 5468 | 2 / 96 | 9 / 661 | 31 / 4711 |
| **ИТОГО** | 88 / 5313 | 327 / 40501 | 20 / 738 | 44 / 3084 | 263 / 36679 |

Порог сходства: 0.3. В строках: как есть 1.8%, переработано 7.6%, новое 90.6%.
```

## Проверка на реальных данных: чувствительность к порогу

Замер, для которого инструмент писался, — архив интернет-магазина на PHP без git-истории: финальный проект учебного примера, слепок 24.09.2018 и архив 24.10.2021. Ниже — доли строк при разных порогах сходства. Считалось по слоям `app/controllers, app/models, app/views, app/widgets, config, vendor/ishop`.

| граница | порог | как есть | переработано | новое |
|---|---|---|---|---|
| курс → 2021 | 0.20 | 1.8 % | 12.4 % | **85.8 %** |
| курс → 2021 | 0.30 | 1.8 % | 11.0 % | **87.2 %** |
| курс → 2021 | 0.50 | 1.8 % | 7.5 % | **90.6 %** |
| 2018 → 2021 | 0.20 | 7.4 % | 35.2 % | **57.3 %** |
| 2018 → 2021 | 0.30 | 7.5 % | 34.5 % | **58.0 %** |
| 2018 → 2021 | 0.50 | 7.4 % | 33.5 % | **59.0 %** |

Что из этого следует:

- **Вывод устойчив к выбору порога.** Доля нового кода меняется на 1–5 процентных пунктов, но соотношение не переворачивается: от учебного примера к финалу унаследовано мало, от слепка 2018 года — заметно больше.
- **Порог двигает границу между «переработано» и «новое», а не между «как есть» и остальным.** Доля дословно совпадающих строк почти не меняется: точное совпадение определяется хешем, а не коэффициентом.
- Поэтому в отчётах имеет смысл указывать порог явно и показывать диапазон, а не одно число.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Фикстуры синтетические: содержимое генерируется во временном каталоге с заранее известным ответом (идентичный файл, переименованный, переработанный, новый). Тесты не требуют сети и не зависят от конкретного проекта.

## Ограничения

- **Порог сходства — параметр, а не истина.** При 0,30 два незнакомых файла с одинаковыми конструкциями языка могут попасть в `modified`. Для честных выводов считайте на двух-трёх порогах (0,30 / 0,50 / 0,70) и показывайте диапазон.
- **Сравнение посимвольное**, не по синтаксическому дереву: смена форматирования и перестановка блоков занижают сходство, а почти полная переработка при сохранении заготовки может его завысить.
- **Предфильтр кандидатов** отбрасывает очень редкие и очень частые 4-граммы и ограничивает число кандидатов для полного сравнения — на больших деревьях это ускоряет работу в разы, но в редких случаях лучший предок может не попасть в список. Числа от этого меняются в пределах долей процента.
- **Строки считаются непустые**: пустые строки и строки из одних пробелов не учитываются, иначе объём зависел бы от стиля форматирования.
- **Не анализирует качество**: инструмент не говорит, лучше или хуже стал код — только что унаследовано, переработано и добавлено.

## Мотивация

Инструмент написан для разбора архива собственного интернет-магазина на PHP (2014–2021), у которого не сохранилось git-истории, но остались два слепка — 2018 и 2021 годов, — плюс исходный учебный пример, с которого проект начинался. Подробности разбора — в статье [«Археология своего кода»](https://alexfdev.ru/blog/legacy-shop-evolution/).
