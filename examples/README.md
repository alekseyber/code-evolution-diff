# Пример: три версии одного магазина

Небольшой срез, на котором видно все три класса результата. Структура повторяет реальную задачу: один и тот же проект в трёх состояниях, без git-истории.

- `course/` — исходный учебный каркас: контроллер, модель, настройки.
- `v2018/` — через четыре года: контроллер переработан, модель не тронута, появился заказ, настройки те же.
- `v2021/` — финал: контроллер вырос дальше, модель переписана, заказ тот же, появилась корзина.

Запуск:

```bash
python3 compare.py --baseline examples/course --target examples/v2021 \
    --layers app,config --format markdown
```

Ожидаемый результат (порог 0.30):

```
| слой | база (файлы/строки) | цель (файлы/строки) | как есть | переработано | новое |
|---|---|---|---|---|---|
| app | 2 / 34 | 4 / 117 | 0 / 0 | 2 / 33 | 2 / 84 |
| config | 1 / 6 | 1 / 6 | 1 / 6 | 0 / 0 | 0 / 0 |
| **ИТОГО** | 3 / 40 | 5 / 123 | 1 / 6 | 2 / 33 | 2 / 84 |

Порог сходства: 0.3. В строках: как есть 4.9%, переработано 26.8%, новое 68.3%.
```

Разбор по файлам:

- `config/params.php` — `identical` по пути и содержимому, 6 строк;
- `app/controllers/ProductController.php` — `modified`: от каркаса остались сигнатуры и рендер, тело методов переписано;
- `app/models/Product.php` — в 2021-й версии переписан так, что общих фрагментов меньше порога: файл считается `new`, а не `modified`. Это ровно тот случай, о котором предупреждает раздел «Ограничения»: при 0.30 сильная переработка уже неотличима от нового файла;
- `app/models/Order.php` — `new` в 2018-м, дальше не менялся;
- `app/models/Cart.php` — `new` в 2021-м.

Чтобы посмотреть сопоставление «кто с кем»:

```bash
python3 compare.py --baseline examples/course --target examples/v2021 \
    --layers app,config --format csv
```

В CSV у каждого файла указан найденный предок и коэффициент сходства — по ним видно, почему файл получил свой класс.
